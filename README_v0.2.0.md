# Flasher Studio v0.2.0 — первый аппаратный релиз-кандидат

Основа: утверждённый UI 20, приложение v0.1.2. Builder v0.2.6 и Bootloaders v0.2.0 не изменяются. Сайт: flasher-studio-byvovk.web.app. Не менять старый ESP Flasher.

## Деплой

Из Google Cloud Shell, после загрузки ZIP:

```sh
cd ~ && unzip -o Flasher_Studio_v0.2.0.zip && cd Flasher_Studio_v0.2.0 && npm install --ignore-scripts --no-audit --no-fund && npm run vendor && npm test && firebase deploy --only hosting:studio --project esp-flasher-byvovk
```

npm собирает локальный USB-модуль из esptool-js 0.7.1, web-serial-polyfill 1.0.15, crypto-js 4.2.0; esbuild 0.25.12. Сторонние модули не загружаются с CDN в рабочей PWA. Сборка npm и деплой не выполнены в нашей среде: сеть недоступна. Точные версии прямых зависимостей указаны, lock-файл npm генерируется при установке. Не пропускать `npm run vendor`.

## Компилятор

По умолчанию `VV-Vovk/flasher-studio-builder`, workflow `build-universal.yml`. Нужен fine-grained PAT, доступ к новому приватному репозиторию: Actions и Contents read/write, Metadata read. Токен только в памяти вкладки. Git Data API отправляет исходники до 15 МиБ в историю main; не загружать секреты. Не-force update ref. При сбоях сети не отправлять повторно вслепую. Автоматическая загрузка артефакта GitHub может быть заблокирована CORS при перенаправлении; в этом случае открыть GitHub Actions, скачать `firmware-<requestID>` и выбрать ZIP в окне сборки. Проверяется запрос, исходный SHA-256, engine/FQBN и хеши файлов/lock-файлов. Данные сохраняются в IndexedDB. Старый ESP Builder можно выбрать в настройках (legacy API). Не очищает старую локальную библиотеку. Динамический каталог STM32 из присланного CI, не гарантия программирования любой модели. FQBN для нераспознанной платы можно указать вручную. Не поддерживаются самостоятельная генерация IOC и специфичные проприетарные проекты. Автоматическая разметка Recovery при компиляции пока не интегрирована.

## Аппаратные функции (реальный код, физически НЕ проверен)

- ESP32, ESP32-C3/S3/C6: USB Serial, esptool-js. Проверка чипа, MAC, объёма Flash, заголовков полного merged BIN, адреса из манифеста, readback SHA-256 после записи. Использовать стандартный merged BIN, не application BIN. Полная запись может заменить таблицу разделов и загрузчик. Secure Boot / Flash Encryption не поддерживаются.
- STM32 системный USART (AN3155): F030F4P6, F030K6T6, F030C8T6, F103C8T6, F103CBT6. BOOT0 и RESET согласно документации платы. UART 115200 8E1. PID не уникален для полной модели: сверяем также объём Flash и UID, пользователь подтверждает выбранную маркировку. Intel HEX от 0x08000000, проверка векторов, полное стирание пользовательской Flash, запись с readback каждого блока. Защиту чтения не снимаем; Option Bytes не изменяем.
- Arduino Uno R3, Nano с новым/старым STK500v1: UART, HEX приложения, проверка сигнатуры и чтение каждой записанной страницы. Наличие штатного загрузчика обязательно. Сигнатура типа не является уникальным ID экземпляра. Urboot, ISP, UPDI, AVR109, STK500v2 пока недоступны.
- ESP BLE Recovery v0.2.0: только уже установленная совместимая служба, токен 128 бит, сопряжение ОС, app-only BIN с подтверждённой разметкой. Проверяются заголовок, тип образа, размер, SHA-256, подтверждение длины и результат команды commit. Запуск новой программы не подтверждается. Установка кандидатов заблокирована.
- Резервное копирование ESP/STM32, проверка ранее записанного диапазона SHA-256. Хранение реального MAC/UID и локальной истории. Информация о последней записи не равна автоматически считанной версии.
- Android: WebUSB polyfill CDC-ACM; CH340/CP210x и конкретные USB-интерфейсы могут не поддерживаться. Desktop Chrome Web Serial предпочтителен. Web Bluetooth зависит от браузера/ОС и pairing. Wi-Fi OTA из HTTPS PWA не готов: HTTP/CORS/Local Network Access. ST-LINK, SWD, DFU, ISP, UPDI, Nordic DFU, RP2040 UF2 и автоустановка загрузчиков пока не реализованы. Без имитаций.

## Проверка

`npm test`: 10 unit-тестов, включая тестовые ответы STM32, AVR, BLE, границы HEX и Git API. Отдельно проверены два настоящих ZIP артефакта CI (ESP32-C3 и STM32G071), app-only vs merged, запуск UI в Chromium mobile viewport через set_content и локально подставленные JS-модули/каталоги (реальная HTTP-навигация запрещена в среде). Нет теста аппаратуры, сборки npm, реального GitHub-запроса или PWA-деплоя. Драйверы — кандидаты для проверки на тестовых платах; сначала резервная копия, не использовать на единственном рабочем устройстве.
